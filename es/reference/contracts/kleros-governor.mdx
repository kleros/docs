KlerosGovernor ejecuta las decisiones de gobernanza tomadas mediante votación fuera de la cadena (Snapshot). Utiliza el arbitraje de Kleros para resolver las disputas cuando se envían varias listas de transacciones en competencia.

## Cómo funciona {#how-it-works}

1. **Periodo de envío**: cualquiera puede enviar, con un depósito, una lista de transacciones para ejecutar
2. **Periodo de aprobación**: si solo se envía una lista, se aprueba automáticamente. Si compiten varias listas, se crea una disputa en Kleros Court
3. **Ejecución**: las transacciones de la lista aprobada se ejecutan en la cadena

## Métodos clave {#key-methods}

### `submitList(address[] _targets, uint256[] _values, bytes _data, uint256[] _dataLengths, string _description)` {#submitlistaddress-_targets-uint256-_values-bytes-_data-uint256-_datalengths-string-_description}
Envía una lista de transacciones para su ejecución por la gobernanza.

### `executeTransactionList(uint256 _listID, uint256 _cursor, uint256 _count)` {#executetransactionlistuint256-_listid-uint256-_cursor-uint256-_count}
Ejecuta transacciones de una lista aprobada. Puede llamarse por partes para gestionar el gas.

### `executeSubmissions()` {#executesubmissions}
Activa el proceso de aprobación. Si hay una lista, la aprueba. Si hay varias, crea una disputa.

## Parámetros {#parameters}

| Parámetro | Descripción |
|---|---|
| `submissionBaseDeposit` | Depósito base exigido por cada lista enviada |
| `submissionTimeout` | Duración del periodo de envío |
| `executionTimeout` | Plazo para ejecutar las transacciones aprobadas |
| `withdrawTimeout` | Periodo de gracia para retirar los depósitos de ejecución |

## Eventos {#events}

| Evento | Descripción |
|---|---|
| `SessionCreated` | Se inicia una nueva sesión de gobernanza |
| `ListSubmitted` | Lista de transacciones enviada |
| `Ruling` | Disputa resuelta, lista ganadora determinada |
