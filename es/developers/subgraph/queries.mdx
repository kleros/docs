# Ejemplos de consultas

Consultas GraphQL comunes para obtener datos de los subgraphs de Kleros.

---

## Consultas core de V2 (Arbitrum)

<Note>
Usa siempre el endpoint de la **red descentralizada** para las consultas en producción. Obtén el ID del subgraph en las páginas de Studio indicadas en [Endpoints de subgraphs](/es/developers/subgraph/endpoints) y construye la URL como `https://gateway.thegraph.com/api/{API_KEY}/subgraphs/id/{SUBGRAPH_ID}`.
</Note>

### Obtener cortes
Campos clave: `minStake` (en wei), `feeForJuror` (recompensa del jurado por voto), `timesPerPeriod` (array con las duraciones de las 4 fases en segundos).

```graphql
{
  courts(first: 20, orderBy: id) {
    id
    hiddenVotes
    minStake
    alpha
    feeForJuror
    jurorsForCourtJump
    timesPerPeriod
    parent { id }
    policy { policy }
    numberDisputes
    numberStakedJurors
    stakedJurors {
      id
    }
  }
}
```

### Obtener disputas recientes
Campos clave: `externalDisputeID` (el ID de tu app), `templateId` (enlaza con DisputeTemplateRegistry), `ruled` (finalizada), `currentRuling` (opción de fallo vigente).

```graphql
{
  disputes(first: 10, orderBy: createdAtBlock, orderDirection: desc) {
    id
    arbitrated { id }
    court { id }

    period
    ruled
    currentRuling
    tied
    overridden
    lastPeriodChange
    nbRounds
    nbChoices
    externalDisputeID
    templateId
    rounds {
      nbVotes
      totalFeesForJurors
      drawnJurors { juror { id } }
    }
  }
}
```
### Obtener una disputa por ID externo

Usa `externalDisputeID` para relacionar una disputa on-chain con el ID interno de tu app (emitido en `DisputeRequest`):

```graphql
query GetDisputeByExternalID($externalId: BigInt!) {
  disputes(where: { externalDisputeID: $externalId }) {
    id
    period
    ruled
    currentRuling
    tied
    templateId
  }
}
```

### Obtener los stakes de jurado de una dirección específica

```graphql
{
  jurorTokensPerCourts(where: { juror: "0xYOUR_ADDRESS_LOWERCASE" }) {
    court { id }
    staked
    locked
  }
}
```
### Obtener los sorteos activos de un jurado

```graphql
query GetJurorDraws($juror: String!) {
  draws(where: { juror: $juror, vote_not: null }, first: 20) {
    dispute { id period currentRuling }
    round { id nbVotes }
    vote { choice }
  }
}
```

## Consultas de Curate (V1)

### Obtener elementos registrados de una lista de Light Curate

```graphql
{
  litems(
    first: 10
    where: {
      status: Registered
      registryAddress: "0xYOUR_LIST_ADDRESS_LOWERCASE"
    }
    orderBy: latestRequestResolutionTime
    orderDirection: desc
  ) {
    itemID
    data
    props {
      type
      label
      description
      value
    }
  }
}
```

### Obtener elementos en período de impugnación

```graphql
{
  litems(
    first: 10
    where: {
      status_in: [RegistrationRequested, ClearingRequested]
      registryAddress: "0xYOUR_LIST_ADDRESS_LOWERCASE"
      disputed: false
    }
    orderBy: latestRequestSubmissionTime
    orderDirection: asc
  ) {
    itemID
    status
    props {
      label
      value
    }
    requests(first: 1, orderBy: submissionTime, orderDirection: desc) {
      submissionTime
      requester
    }
  }
}
```

### Obtener detalles de un elemento con su historial de solicitudes

```graphql
query ItemDetails($id: ID!) {
  item(id: $id) {
    data
    requests(orderBy: submissionTime, orderDirection: desc) {
      requestType
      disputed
      disputeID
      submissionTime
      resolved
      requester
      challenger
      rounds(orderBy: creationTime, orderDirection: desc) {
        appealPeriodStart
        appealPeriodEnd
        ruling
        hasPaidRequester
        hasPaidChallenger
      }
    }
  }
}
```

Los ID de elementos en el subgraph usan el formato `<itemID>@<listAddress>`:

```typescript
const compoundId = `${itemID}@${tcrAddress.toLowerCase()}`;
const result = useQuery(ITEM_DETAILS_QUERY, { variables: { id: compoundId } });
```

## Registros de etiquetas de direcciones (Gnosis Chain)

Consulta por lotes para obtener etiquetas de direcciones de los tres registros de etiquetas de direcciones de Kleros en Gnosis Chain:

```graphql
{
  contractDomainTags: litems(
    where: {
      status_in: [Registered, ClearingRequested]
      registryAddress: "0x CONTRACT_DOMAIN_TAG_REGISTRY"
    }
    first: 1000
  ) {
    props { label value }
  }
  addressTags: litems(
    where: {
      status_in: [Registered, ClearingRequested]
      registryAddress: "0x ADDRESS_TAG_REGISTRY"
    }
    first: 1000
  ) {
    props { label value }
  }
}
```

Subgraph: [legacy-curate-gnosis](https://thegraph.com/explorer/subgraphs/9hHo5MpjpC1JqfD3BsgFnojGurXRHTrHWcUcZPPCo6m8) en Graph Explorer (ID del subgraph `9hHo5MpjpC1JqfD3BsgFnojGurXRHTrHWcUcZPPCo6m8`)

## Proof of Humanity

### Comprobar el estado de registro

```graphql
{
  submission(id: "0xADDRESS_LOWERCASE") {
    registered
    name
    creationTime
    status
    requests(first: 1, orderBy: creationTime, orderDirection: desc) {
      evidence {
        URI
      }
    }
  }
}
```

Como alternativa, llama a `isRegistered(address)` directamente en el contrato de PoH en `0xC5E9dDebb09Cd64DfaCab4011A0D5cEDaf7c9BDb`.

---

## Consejos

- Las direcciones deben estar en **minúsculas** en todas las consultas. El subgraph las almacena como bytes y no entiende las direcciones con checksum.
- Los elementos con estado `ClearingRequested` siguen registrados hasta que la solicitud de eliminación se finaliza. Inclúyelos al obtener elementos "activos".
- El servicio alojado de The Graph tiene un **límite de 1000 elementos** por consulta. Para registros con más elementos, pagina usando `skip` o `id_gt`.
- Las entidades de Light Curate llevan el prefijo `l` (p. ej., `litems`, `lrequests`). Classic Curate usa entidades sin prefijo (`items`, `requests`).
