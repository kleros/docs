# Construir con Vea {#build-with-vea}

Esta página explica cómo integrar Vea en una aplicación entre cadenas. Para los detalles a nivel de protocolo, consulta la [descripción general de Vea Bridge](/developers/crosschain/vea-bridge).

---

## Patrón de integración {#integration-pattern}

Para integrar Vea, despliegas dos contratos gateway:

1. Un **Sender Gateway** en la cadena de envío, que se comunica con VeaInbox
2. Un **Receiver Gateway** en la cadena de recepción, que se comunica con VeaOutbox

```
Sender Gateway (Chain A) -> VeaInbox -> [Vea Bridge] -> VeaOutbox -> Receiver Gateway (Chain B)
```

Para cada par de cadenas de envío y recepción que admite Vea hay un conjunto separado de despliegues de contratos de Vea. En cada cadena hay exactamente un contrato desplegado.

---

## 1. Sender Gateway {#1-sender-gateway}

El Sender Gateway llama a `sendMessage()` en VeaInbox para iniciar la comunicación entre cadenas.

```solidity
interface IVeaInbox {
    function sendMessage(
        address _to,        // address of Receiver Gateway on destination chain
        bytes4 _fnSelector, // function selector to call on Receiver Gateway
        bytes memory _data  // encoded parameters
    ) external;
}
```

Especificas:
- La dirección del contrato de destino en la cadena de recepción (`_to`)
- La función que se llamará en el destino (`_fnSelector`)
- Los parámetros codificados (`_data`)

### Ejemplo: Sender Gateway {#example-sender-gateway}

```solidity
contract SenderGateway {
    IVeaInbox public immutable veaInbox;
    address public immutable receiverGateway;

    constructor(IVeaInbox _veaInbox, address _receiverGateway) {
        veaInbox = _veaInbox;
        receiverGateway = _receiverGateway;
    }

    function sendMyMessage(uint256 _data) external {
        bytes4 selector = IReceiverGateway.receiveMessage.selector;
        bytes memory data = abi.encode(_data);
        veaInbox.sendMessage(receiverGateway, selector, data);
    }
}
```

---

## 2. Receiver Gateway {#2-receiver-gateway}

El Receiver Gateway recibe el mensaje transmitido en la cadena de destino. Vea pasa el `msg.sender` de la cadena de envío como primer argumento de cualquier llamada entre cadenas.

```solidity
interface IReceiverGateway {
    function veaOutbox() external view returns (address);
    function senderGateway() external view returns (address);
}
```

Tu función receptora siempre debe incluir `address msgSender` como primer parámetro:

```solidity
contract ReceiverGateway is IReceiverGateway {
    address public override veaOutbox;
    address public override senderGateway;

    modifier onlyFromVea() {
        require(msg.sender == veaOutbox, "Only VeaOutbox");
        _;
    }

    function receiveMessage(address msgSender, uint256 _data) external onlyFromVea {
        require(msgSender == senderGateway, "Only SenderGateway");
        // Process _data
    }
}
```

<Warning>
Vea inserta el parámetro `msgSender` por seguridad. Tu interfaz siempre debe tener `address msgSender` como primer argumento. Los parámetros que enviaste van a continuación.
</Warning>

## 3. Transmitir los mensajes {#3-relaying-messages}

Una vez transcurrido el periodo de impugnación, un relayer llama a `verifyAndRelay()` en VeaOutbox para entregar el mensaje al Receiver Gateway.

El SDK de Vea ofrece funciones auxiliares para calcular las pruebas de inclusión de Merkle y obtener los datos de los mensajes que se van a transmitir:

```typescript
import VeaSdk from "@kleros/vea-sdk";

// Create client for a specific route
  const vea = VeaSdk.ClientFactory.arbitrumSepoliaToChiadoDevnet(
  "https://sepolia-rollup.arbitrum.io/rpc",
  "https://rpc.chiadochain.net"
  
);

// Get message info by ID
const messageInfo = await vea.getMessageInfo(messageId);

// Calculate proof and relay
// ... relay logic using proof data
```

<Note>
El SDK está en desarrollo activo. Consulta el [paquete del SDK de Vea](https://github.com/kleros/vea) para ver la API más reciente.
</Note>

## Demo Lightbulb {#lightbulb-demo}

La [demo Vea Lightbulb](https://docs.vea.ninja/build-xchain-dapps/lightbulb-demo) es una aplicación mínima entre cadenas en la que un interruptor en una cadena controla una bombilla en otra mediante Vea. El [repositorio del tutorial](https://github.com/kleros/vea-lightbulb-tutorial) explica cómo desplegar los contratos para cada par de cadenas.

El estado del puente se puede seguir en [VeaScan](https://veascan.io).
