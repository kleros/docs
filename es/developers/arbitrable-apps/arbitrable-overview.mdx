## ¿Qué es un contrato arbitrable? {#what-is-an-arbitrable-contract}

Un contrato arbitrable es cualquier contrato inteligente que puede crear disputas y ejecutar los fallos de Kleros. Tu contrato implementa una interfaz arbitrable (`IArbitrableV2` en Kleros V2, ERC-792 en V1), que define dos cosas:

1. **Cómo se crean las disputas**: tu contrato decide cuándo surgen los conflictos
2. **Cómo se ejecutan los fallos**: tu contrato ejecuta el resultado

Kleros se encarga de todo lo que ocurre entremedias: la selección de jurados, la votación, las apelaciones y la determinación del fallo final.

<Note>
Esta sección incluye tanto las guías de contratos arbitrables de V2 (`IArbitrableV2`) como los estándares del protocolo V1, [ERC-792](/es/developers/arbitrable-apps/erc-792) y [ERC-1497](/es/developers/arbitrable-apps/erc-1497), junto con sus referencias de integración ([Aplicaciones arbitrables V1](/es/developers/arbitrable-apps/v1-arbitrable-apps), [Árbitro centralizado](/es/developers/arbitrable-apps/centralized-arbitrator), [Arbitrable Proxy](/es/developers/arbitrable-apps/arbitrable-proxy)).
</Note>

## Cuándo usar el arbitraje de Kleros {#when-to-use-kleros-arbitration}

<CardGroup cols={2}>
  <Card title="Buen encaje" icon="check">
    - Disputas subjetivas que pueden juzgar personas
    - Transacciones de alto valor que justifican el coste
    - Casos en los que la confianza es imposible

  </Card>

## Decisiones de diseño clave {#key-design-decisions}

Antes de escribir código, decide lo siguiente:

### 1. Opciones de fallo {#1-ruling-options}

Define qué pueden decidir los jurados. Patrones habituales:

| Patrón | Opciones | Ejemplo |
|---------|---------|---------|
| Binario | 2 | Liberar los fondos: Sí / No |
| Varias partes | 3+ | Ganador: Alice / Bob / Reparto |
| Graduado | N | Porcentaje de reembolso: 0% / 25% / 50% / 75% / 100% |

<Note>
La opción `0` está reservada para "Negarse a arbitrar": los jurados la eligen cuando la disputa no es válida o no tiene respuesta.
</Note>

### 2. ¿Quién paga las tasas? {#2-who-pays-fees}

El arbitraje cuesta ETH. Tu contrato decide quién paga:

```mermaid

    subgraph Patrones de pago de tasas
        A["Paga el reclamante"] -->|Efecto| A1["Desalienta las reclamaciones frívolas"]
        B["Paga el perdedor"] -->|Efecto| B1["Requiere depósitos por adelantado<br/>Lo usan Escrow V2 y Curate V2"]
        C["Reparto 50/50"] -->|Efecto| C1["Justo pero complejo"]
        D["Paga el protocolo"] -->|Efecto| D1["Disputas subvencionadas"]
    end
    style A fill:#7b5ea7,color:#fff
    style B fill:#7b5ea7,color:#fff
    style C fill:#9b8ec4,color:#fff
    style D fill:#9b8ec4,color:#fff
```

<Note>
La mayoría de los productos de Kleros usan el modelo de **paga el perdedor**: ambas partes depositan la tasa de arbitraje por adelantado y al ganador se le reembolsa. Es el patrón que usan Escrow V2 y Curate V2.
</Note>

### 3. Desencadenantes de las disputas {#3-dispute-triggers}

¿Cuándo empieza una disputa? Desencadenantes habituales:

- **Solicitud explícita**: una parte llama a `raiseDispute()`
- **Tiempo agotado**: no hay respuesta dentro del plazo
- **Impugnación**: alguien disputa una acción pendiente
- **Automático**: se detectan reclamaciones contradictorias

### 4. Presentación de evidencias {#4-evidence-submission}

Decide cómo llegan las evidencias a los jurados:

- **Eventos en la cadena**: emite eventos `Evidence` desde tu contrato
- **Módulo separado**: usa el contrato `EvidenceModule`
- **Entre cadenas**: evidencias desde una cadena externa mediante el gateway

## Requisitos de la interfaz (V2) {#interface-requirements-v2}

<Note>
Esta sección es específica de Kleros V2. En V1, los contratos implementan [ERC-792](/es/developers/arbitrable-apps/erc-792) y [ERC-1497](/es/developers/arbitrable-apps/erc-1497) y deben emitir un evento `MetaEvidence` para que la interfaz de Court pueda mostrar la disputa.
</Note>

Para integrarse con Kleros V2, tu contrato debe implementar:

```solidity
interface IArbitrableV2 {
    /// @dev Emitted when a dispute is created
    event DisputeRequest(
        IArbitratorV2 indexed _arbitrator,
        uint256 indexed _arbitratorDisputeID,
        uint256 _externalDisputeID,
        uint256 _templateId,
        string _templateUri
    );
    
    /// @dev Emitted when a ruling is executed
    event Ruling(
        IArbitratorV2 indexed _arbitrator,
        uint256 indexed _disputeID,
        uint256 _ruling
    );
    
    /// @dev Called by arbitrator to deliver ruling
    function rule(uint256 _disputeID, uint256 _ruling) external;
}
```

## Patrones de arquitectura {#architecture-patterns}

### Patrón A: integración directa {#pattern-a-direct-integration}

Tu contrato es el arbitrable. Es el enfoque más sencillo.

```mermaid
sequenceDiagram
    participant User as Usuario
    participant YourContract as Tu contrato<br/>(IArbitrableV2)
    participant Kleros as KlerosCore

    User->>YourContract: desencadena la disputa
    YourContract->>Kleros: createDispute{value: fee}()
    Kleros-->>YourContract: disputeID
    Note over Kleros: Sorteo de jurados, votación, apelación...
    Kleros->>YourContract: rule(disputeID, ruling)
    YourContract->>YourContract: ejecuta el fallo
```

### Patrón B: proxy/resolver {#pattern-b-proxy/resolver}

Usa `DisputeResolver` como intermediario. Es adecuado para la actualizabilidad.

```mermaid
sequenceDiagram
    participant User as Usuario
    participant YourContract as Tu contrato
    participant DR as DisputeResolver
    participant Kleros as KlerosCore
    participant TR as TemplateRegistry

    User->>YourContract: desencadena la disputa
    YourContract->>DR: createDisputeForTemplate()
    DR->>TR: setDisputeTemplate()
    TR-->>DR: templateId
    DR->>Kleros: createDispute{value: fee}()
    Kleros-->>DR: disputeID
    Note over Kleros: Sorteo de jurados, votación, apelación...
    Kleros->>DR: rule(disputeID, ruling)
    DR->>YourContract: reenvía el fallo
```

### Patrón C: entre cadenas {#pattern-c-cross-chain}

El contrato arbitrable está en mainnet y la resolución, en Arbitrum.

```mermaid
sequenceDiagram
    box Cadena externa (p. ej., Ethereum)
        participant User as Usuario
        participant App as Tu contrato
        participant FG as ForeignGateway
    end
    box Arbitrum (cadena principal)
        participant HG as HomeGateway
        participant Kleros as KlerosCore
    end

    User->>App: desencadena la disputa
    App->>FG: createDispute{value: fee}()
    FG-->>App: localDisputeID
    FG->>HG: Puente Vea (Simple Bridge)
    HG->>Kleros: createDispute()
    Note over Kleros: Sorteo de jurados, votación, apelación...
    Kleros->>HG: rule(disputeID, ruling)
    HG->>FG: Puente Vea (Fast Bridge)
    FG->>App: rule(localDisputeID, ruling)
```

## Consideraciones de coste {#cost-considerations}

| Factor | Impacto |
|--------|--------|
| Número de jurados | Más jurados = tasas más altas, más seguridad |
| Selección del tribunal | Los tribunales especializados pueden costar más |
| Apelaciones | Cada ronda duplica aproximadamente el coste |
| Almacenamiento de evidencias | Los costes de IPFS/Arweave van aparte |

<Tip>
Empieza con **3 jurados** en el **General Court** para la mayoría de las disputas. Aumenta el número en los casos de alto valor.
</Tip>

## Mentalidad de seguridad {#security-mindset}

Tu contrato debe gestionar:

- **Reentrada**: `rule()` es una llamada externa
- **Validación del fallo**: comprueba que el fallo está dentro del rango esperado
- **Fallos duplicados**: evita que `rule()` se llame dos veces
- **Cambios de tasas**: el coste del arbitraje puede cambiar entre llamadas
- **Confianza en el árbitro**: acepta fallos solo de tu árbitro
