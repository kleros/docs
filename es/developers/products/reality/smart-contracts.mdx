## Direcciones de los proxies de árbitro de Kleros {#kleros-arbitrator-proxy-addresses}

El proxy de árbitro se sitúa entre Reality.eth y Kleros Court. Al formular una pregunta en Reality.eth, pasas la dirección del proxy como parámetro `arbitrator`.

### Ethereum Mainnet {#ethereum-mainnet}

| Proxy           | Tribunal                  | Dirección                                      |
| --------------- | ---------------------- | -------------------------------------------- |
| General Court   | General                | `0x728cba71a3723caab33ea416cb46e2cc9215a596` |
| Technical Court | Blockchain > Technical | `0xf72cfd1b34a91a64f9a98537fe63fbab7530adca` |

### Testnet Sepolia {#sepolia-testnet}

| Proxy         | Tribunal   | Dirección                                      |
| ------------- | ------- | -------------------------------------------- |
| General Court | General | `0x05b942faecfb3924970e3a28e0f230910cedff45` |



### Proxies entre cadenas {#cross-chain-proxies}

Para los despliegues en los que la pregunta está en una cadena y el arbitraje se realiza en otra (por ejemplo, la pregunta en Polygon y el arbitraje en Ethereum), consulta los [despliegues de cross-chain-realitio-proxy](https://github.com/kleros/cross-chain-realitio-proxy/tree/master/contracts#deployments).

<Note>
  Cada proxy se configura con un subtribunal, un número inicial de votos de jurados y una tasa de arbitraje concretos. Escribe a `integrations@kleros.io` para desplegar un proxy personalizado para tu caso de uso.
</Note>

## Interfaz de Reality.eth {#reality-eth-interface}

Tu contrato interactúa con Reality.eth mediante estas funciones principales.

### Formular preguntas {#asking-questions}

```solidity theme={null}
/// @dev Ask a question on Reality.eth with a Kleros arbitrator.
/// @param templateID The question template (0=bool, 1=uint, 2=single-select, etc.)
/// @param question The question string with parameters separated by ␟ delimiter
/// @param arbitrator The Kleros arbitrator proxy address
/// @param timeout Seconds before an unchallenged answer finalizes (max 365 days)
/// @param openingTimestamp When the question becomes answerable (0 for immediately)
/// @param nonce Unique nonce for question deduplication
/// @return questionID The unique identifier for the question
function askQuestion(
    uint256 templateID,
    string calldata question,
    address arbitrator,
    uint32 timeout,
    uint32 openingTimestamp,
    uint256 nonce
) external payable returns (bytes32 questionID);
```

Cualquier ETH enviado con esta llamada se convierte en la recompensa de la pregunta, que se paga a quien da la respuesta final aceptada (menos cualquier deducción por la tasa del árbitro).

Para los tokens de recompensa ERC20, usa `askQuestionERC20()`.

### Leer las respuestas {#reading-answers}

```solidity theme={null}
/// @dev Returns the finalized answer for a question.
/// Reverts if the question has not been finalized.
function resultFor(bytes32 _questionID) external view returns (bytes32);

/// @dev Returns the best current answer (may not be finalized).
function getBestAnswer(bytes32 _questionID) external view returns (bytes32);

/// @dev Returns true if the question has been finalized.
function isFinalized(bytes32 _questionID) external view returns (bool);

/// @dev Returns the timestamp when the current answer will finalize.
function getFinalizeTS(bytes32 _questionID) external view returns (uint32);
```

<Warning>
  `resultFor()` se revierte cuando la pregunta todavía no está finalizada. Comprueba siempre primero `isFinalized()`, usa un envoltorio try/catch o usa el patrón de callback que se muestra en la [guía de integración](/es/developers/products/reality/integration#step-3-handle-the-callback-optional).
</Warning>

### Enviar respuestas {#submitting-answers}

```solidity theme={null}
/// @dev Submit an answer. Bond must be at least 2x the current bond.
/// @param _maxPrevious Caller's expected current bond, for safety against front-running.
function submitAnswer(
    bytes32 _questionID,
    bytes32 _answer,
    uint256 _maxPrevious
) external payable;
```

### Solicitar el arbitraje {#requesting-arbitration}

```solidity theme={null}
/// @dev Request arbitration from the specified arbitrator.
/// Requires payment of the arbitration fee.
function notifyOfArbitrationRequest(
    bytes32 _questionID,
    address _requester,
    uint256 _maxPrevious
) external;
```

Para consultar la tasa de arbitraje actual:

```solidity theme={null}
uint256 fee = realityETH.getArbitrator(_questionID).getDisputeFee(_questionID);
```

## Formato de las preguntas {#question-format}

Las preguntas usan el delimitador Unicode `␟` (U+241F) para separar los campos. El formato exacto depende de la plantilla.

```
// Template 0 (bool):
"Did event X happen?␟category␟en"

// Template 1 (uint):
"What was the price of ETH on April 16, 2025?␟crypto␟en"

// Template 2 (single-select):
"Which team won?␟\"Option A\",\"Option B\",\"Option C\"␟category␟en"

// Template 3 (multiple-select):
"Which proposals passed?␟\"Prop A\",\"Prop B\",\"Prop C\"␟governance␟en"

// Template 4 (datetime):
"When did event X occur?␟history␟en"

// Template 5 (hash) - added in v3.2:
"Does this hash correspond to the document?␟verification␟en"
```

Las definiciones de las plantillas estándar:

```
0: {"title": "%s", "type": "bool", "category": "%s", "lang": "%s"}
1: {"title": "%s", "type": "uint", "decimals": 18, "category": "%s", "lang": "%s"}
2: {"title": "%s", "type": "single-select", "outcomes": [%s], "category": "%s", "lang": "%s"}
3: {"title": "%s", "type": "multiple-select", "outcomes": [%s], "category": "%s", "lang": "%s"}
4: {"title": "%s", "type": "datetime", "category": "%s", "lang": "%s"}
```

## Interpretación de los resultados {#result-interpretation}

Las respuestas se devuelven como `bytes32`. Cómo decodificarlas depende de la plantilla.

| Plantilla          | Codificación                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| `bool`            | `0x00...01` = Sí, `0x00...00` = No                                                            |
| `uint`            | El número, en bytes32. Divídelo entre `10**decimals` si la plantilla especifica decimales.           |
| `single-select`   | Selección con índice desde cero (`0` = primera opción, `1` = segunda, etc.)                                |
| `multiple-select` | Selección bit a bit (`1` = primera, `2` = segunda, `4` = tercera; `3` = primera + segunda, etc.)         |
| `datetime`        | Marca de tiempo Unix (segundos desde 1970), como bytes32                                                |
| `hash`            | El hash enviado                                                                             |

### Valores especiales {#special-values}

En las respuestas aparecen dos valores bytes32 reservados:

- `0xff...ff` (todo `f`): **no válida**. La pregunta no tiene respuesta, es ambigua o incumple la política de las preguntas. Gestiona siempre este caso en tu contrato.
- `0xff...fe` (todo `f` salvo el último dígito): **respondida demasiado pronto**. La pregunta se formuló antes de que el evento subyacente pudiera resolverse. Puede volver a formularse una vez que haya ocurrido el evento.

```solidity theme={null}
bytes32 constant ANSWERED_INVALID = bytes32(type(uint256).max);
bytes32 constant ANSWERED_TOO_EARLY = bytes32(type(uint256).max - 1);

function isInvalid(bytes32 _answer) public pure returns (bool) {
    return _answer == ANSWERED_INVALID;
}
```

Ejemplos de decodificación:

```solidity theme={null}
// Bool: convert bytes32 to bool
function toBool(bytes32 _answer) public pure returns (bool) {
    return _answer == bytes32(uint256(1));
}

// Uint with 18 decimals (e.g. ETH price)
function toUint(bytes32 _answer) public pure returns (uint256) {
    return uint256(_answer) / 1e18;
}

// Single-select option index
function toIndex(bytes32 _answer) public pure returns (uint256) {
    return uint256(_answer);
}

// Multiple-select: check if option N is selected (zero-indexed)
function isSelected(bytes32 _answer, uint8 _optionIndex) public pure returns (bool) {
    return uint256(_answer) & (1 << _optionIndex) != 0;
}

// Datetime
function toTimestamp(bytes32 _answer) public pure returns (uint256) {
    return uint256(_answer);
}
```

## Flujo del arbitraje {#arbitration-flow}

Cuando se solicita el arbitraje:

1. Quien lo solicita paga la tasa de arbitraje al Kleros Arbitrator Proxy
2. El proxy crea una disputa en Kleros Court con el subtribunal y el número de jurados configurados
3. Se abre el periodo de evidencias; las partes envían las evidencias mediante el contrato proxy
4. Los jurados votan según la pregunta y las evidencias presentadas
5. Cuando el fallo es definitivo, el proxy llama a `submitAnswerByArbitrator()` en Reality.eth
6. Reality.eth finaliza la respuesta según el fallo del árbitro

```mermaid theme={null}
sequenceDiagram
    participant User as Usuario
    participant Reality as Reality.eth
    participant Proxy as Kleros Arbitrator Proxy
    participant Court as Kleros Court

    User->>Reality: requestArbitration()
    Reality->>Proxy: Reenvía la solicitud de arbitraje
    Proxy->>Court: createDispute()
    Note over Court: Periodo de evidencias, votan los jurados
    Court->>Proxy: rule(disputeID, ruling)
    Proxy->>Reality: submitAnswerByArbitrator()
    Reality-->>User: Respuesta finalizada
```

## Presentación de evidencias {#evidence-submission}

Las evidencias se envían a través del contrato Kleros Arbitrator Proxy, no de Reality.eth.

```solidity theme={null}
/// @dev Submit evidence for an ongoing arbitration.
/// @param _questionID The Reality.eth question identifier
/// @param _evidenceURI IPFS URI pointing to the evidence JSON
function submitEvidence(bytes32 _questionID, string calldata _evidenceURI) external;
```

El JSON de las evidencias sigue el formato estándar de [ERC-1497](https://github.com/ethereum/EIPs/issues/1497):

```json theme={null}
{
  "name": "Price data from CoinGecko",
  "description": "Screenshot showing ETH price on the specified date",
  "fileURI": "/ipfs/QmExample...",
  "fileHash": "QmExample...",
  "fileTypeExtension": "png"
}
```

Cualquiera puede presentar evidencias durante el periodo de evidencias, y se admiten varios envíos. Para ver el flujo completo de presentación de evidencias, las pautas de formato y los patrones de supervisión de eventos, consulta [Guía de integración → Presentación de evidencias](/es/developers/products/reality/integration#evidence-submission).

## Tasas y pagos {#fees-and-payments}

El sistema Reality.eth + Kleros implica varios tipos de tasas, cada uno con una función concreta en la estructura de incentivos.

| Tipo de tasa         | La fija           | La paga                  | Se paga a                                                |
| ---------------- | ---------------- | ------------------------ | ------------------------------------------------------ |
| Recompensa de la pregunta  | Quien pregunta            | Quien pregunta                    | Quien dio la respuesta correcta con la fianza más alta\*                      |
| Fianza de la respuesta      | Quien responde         | Quien responde                 | Se devuelve si es correcta; si no, a la siguiente respuesta correcta |
| Tasa de sustitución     | La fianza anterior    | La respuesta siguiente      | Quien respondió antes (se deduce de las recompensas)              |
| Tasa de arbitraje  | El árbitro       | Cualquiera que lo solicite        | El árbitro                                             |
| Tasa de reclamación (2,5%) | El sistema           | Quien reclama                  | Se quema (se deduce del importe reclamado)                  |

\*Cuando se resuelve por arbitraje, el árbitro especifica quién recibe la recompensa.

Para conocer todos los detalles de cada tasa (incluido que la tasa de sustitución es igual a la fianza de quien respondió antes y cuándo se aplica la quema del 2,5% de la tasa de reclamación en Reality.eth v2.1+), consulta [Guía de integración → Tasas y pagos](/es/developers/products/reality/integration#fees-and-payments).
