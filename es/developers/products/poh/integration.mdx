# Guía de integración de Proof of Humanity 2.0 {#proof-of-humanity-2-0-integration-guide}

Esta guía está dirigida a los desarrolladores que quieren verificar si una dirección pertenece a un humano registrado.

<Note>
Los integradores consumen la identidad mediante **CrossChainProofOfHumanity**. Quienes operan PoH gestionan el registro mediante **ProofOfHumanity**. Si estás integrando PoH en una aplicación, solo necesitas CrossChainProofOfHumanity.
</Note>

---

## Inicio rápido: verifica a un humano {#quick-start-verify-a-human}

Usa `CrossChainProofOfHumanity` como contrato de integración en todas las cadenas compatibles. Expone tanto las humanidades registradas localmente como las sincronizadas entre cadenas.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

interface ICrossChainProofOfHumanity {
    function isHuman(address account) external view returns (bool);
    function humanityOf(address account) external view returns (bytes20);
}

contract HumanOnly {
    ICrossChainProofOfHumanity public immutable proofOfHumanity;

    error NotHuman();

    constructor(address crossChainProofOfHumanity) {
        proofOfHumanity = ICrossChainProofOfHumanity(crossChainProofOfHumanity);
    }

    modifier onlyHuman() {
        if (!proofOfHumanity.isHuman(msg.sender)) revert NotHuman();
        _;
    }

    function humanOnlyAction() external onlyHuman {
        // Application logic
    }
}
```

### Direcciones de CrossChainProofOfHumanity {#crosschainproofofhumanity-addresses}

| Red | CrossChainProofOfHumanity |
| --- | --- |
| Ethereum Mainnet | `0xa478095886659168E8812154fB0DE39F103E74b2` |
| Gnosis Chain | `0x16044E1063C08670f8653055A786b7CC2034d2b0` |

- Usa `isHuman(address)` cuando solo necesites verificar que es un humano.
- Usa `humanityOf(address)` y almacena los datos de la aplicación por ID de humanidad cuando la identidad deba sobrevivir a los cambios de billetera.

<Warning>
El estado entre cadenas se entrega mediante la sincronización de los puentes, por lo que un registro, una revocación o una transferencia recientes pueden no aparecer de inmediato en otra cadena.
</Warning>

## Consulta de la identidad {#identity-lookup}

Una vez que tienes un `humanityId` a partir de `humanityOf(address)`, estas funciones de solo lectura ofrecen más detalles:

```solidity
function isClaimed(bytes20 _humanityId) external view returns (bool);
function boundTo(bytes20 _humanityId) external view returns (address);
```

| Función | Propósito |
| --- | --- |
| `isClaimed(humanityId)` | Devuelve true si el ID de humanidad está reclamado activamente |
| `boundTo(humanityId)` | Devuelve la dirección de billetera vinculada actualmente a un ID de humanidad |

Para consultar el estado completo de una humanidad (estado de los avales, solicitudes pendientes, vencimiento, propietario) mediante `getHumanityInfo(humanityId)`, y las funciones de gestión del registro que usan los operadores, consulta la referencia de [contratos inteligentes](/developers/products/poh/smart-contracts).

## Diseño de la identidad soulbound {#soulbound-identity-design}

PoH V2 sigue el principio: **1 humano → 1 ID de humanidad ↔ 1 dirección de billetera**.

El `humanityId` es un identificador soulbound que persiste entre cambios de billetera. Si un usuario pierde el acceso a su billetera, puede volver a registrarse con una nueva dirección conservando el mismo `humanityId`. Las aplicaciones que asocian la reputación, los activos o el historial al `humanityId` en lugar de a la dirección los conservan cuando el usuario cambia de billetera.

```
humanity.owner == lostAddress      // Lost access
humanity.owner == address(0)       // Removal requested
humanity.owner == newAddress       // Re-registered with new wallet
```

<Note>
Los usuarios de V1 tienen un `humanityId` igual a su dirección de registro original (`bytes20(address)`). Los usuarios de V2 reciben un nuevo `humanityId` único al registrarse. La llamada a `isHuman()` cubre automáticamente los registros de V1 mediante el Fork Module.
</Note>
